# Home Pager для ALT Linux

Пакет `home-pager`, версия `0.1.2-alt1`. Репозиторий содержит исходники,
веб-интерфейс и Go-зависимости в `vendor`. При сборке доступ к сети не нужен;
Node.js и npm не требуются. Нужен Go 1.23 или новее и ALT RPM/gear.

## Сборка

В ALT Linux установите инструменты (от root):

```sh
apt-get install gear rpm-build rpm-macros-systemd golang
```

Из корня закоммиченного репозитория, от обычного пользователя:

```sh
gear-rpm -ba
```

Для изолированной сборки в настроенном hasher:

```sh
gear-hsh --no-sisyphus-check=gpg,packager
```

Отключения проверок подписи и Packager нужны для локальной сборки без учётной
записи ALT Team. Для публикации в ALT репозитории оформите Packager и подпись
по требованиям целевого репозитория и запустите проверки без этих исключений.

Gear экспортирует файлы из Git-коммита, поэтому перед следующей сборкой
зафиксируйте изменения. Версия и release задаются в `home-pager.spec`.
При обновлении зависимостей выполните `go mod vendor` до сборки и закоммитьте
`go.mod`, `go.sum` и `vendor`. Скрипт сборки использует `-mod=vendor`,
`GOTOOLCHAIN=local`, `GOPROXY=off`, `GOSUMDB=off`.

## Установка и запуск

Установите собранный RPM (от root), затем проверьте конфиг:

```sh
rpm -Uvh home-pager-0.1.2-alt1.*.rpm
editor /etc/home-pager/home-pager.yaml
systemctl enable --now home-pager.service
systemctl status home-pager.service
journalctl -u home-pager.service
```

По умолчанию панель доступна только на `http://127.0.0.1:8090`, пароль пустой.
Для доступа из сети задайте нужный адрес в `listen`; пароль необязателен.
После изменения стартового конфига перезапустите `home-pager.service`.
Конфиг установлен как `%config(noreplace)` и не перезаписывается при обновлении.
Сервис не включается явно установочным скриптом: запуском управляет администратор
и штатная политика ALT для сервисов. Системный пользователь и данные при удалении
пакета не удаляются установочными скриптами.

Пути:

| Назначение | Путь |
|---|---|
| Бинарь | `/usr/bin/home-pager` |
| Конфиг панели | `/etc/home-pager/home-pager.yaml` |
| YAML/CSS/JS Homepage и история изменений | `/var/lib/home-pager/config` |
| Загруженные иконки | `/var/lib/home-pager/icons` |
| Загруженные фоны | `/var/lib/home-pager/images` |

Homepage не входит в RPM. Укажите панели каталог существующей конфигурации
Homepage либо подключите указанные каталоги к отдельной установке Homepage.
Пользователю `home-pager` нужны права чтения и записи в каталог конфигурации,
иконок и фонов; процессу Homepage — права чтения. Для совместного доступа
настройте общую группу/ACL с учётом UID/GID контейнера. Пакет не меняет владельцев
существующих каталогов Homepage и не управляет Docker.

Если Homepage работает в контейнере, подключите соответствующие каталоги к
`/app/config`, `/app/public/icons` и `/app/public/images`. Для новых локальных
файлов может понадобиться перезапуск Homepage из-за кеширования public-файлов
Next.js; динамическую раздачу `/icons/` и `/images/` можно настроить на прокси.

`ProtectSystem=full` делает `/etc` недоступным для записи сервиса, кроме
`/etc/home-pager`: для него задано `ReadWritePaths`, а группа `home-pager`
имеет право записи в каталог и конфиг. Это позволяет редактировать стартовый
конфиг через GUI и создавать резервные копии рядом с ним. Остальные файлы
Homepage по умолчанию расположены в `/var/lib`. Текущий пароль не передаётся
формой в браузер; доступен выбор оставить пароль, заменить или отключить.
Изменения стартового конфига применяются после перезапуска Home Pager.

## Проверка

В `%check` выполняются Go-тесты. DOM-тесты интерфейса выполняются отдельно
в среде разработки через `npm ci` и `npm test`; для них нужен собранный
локальный бинарь `home-pager` (`home-pager.exe` в Windows).

Использованы инструкции [ALT по сборке пакетов](https://docs.altlinux.org/ru-RU/platform/11.0/html-single/alt-platform/index.html)
и [Gear](https://github.com/altlinux/gear).

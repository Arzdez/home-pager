# Home Pager

Самостоятельная веб-панель на Go для редактирования конфигурации [Homepage](https://gethomepage.dev/). Один бинарник со встроенным интерфейсом на русском языке. Node.js и сборка frontend для запуска не нужны.

Для ALT Linux подготовлены [RPM spec](home-pager.spec), `.gear/rules`,
systemd-сервис и стартовый конфиг. Сборка и установка описаны в
[инструкции ALT Linux](packaging/altlinux/README.alt.md).

## Запуск

Требуется Go 1.23 или новее:

```sh
go build -o home-pager .
cp home-pager.example.yaml home-pager.yaml
# Укажите свои каталоги в home-pager.yaml.
./home-pager -conf ./home-pager.yaml
```

Windows (PowerShell):

```powershell
go build -o home-pager.exe .
Copy-Item home-pager.example.yaml home-pager.yaml
.\home-pager.exe -conf .\home-pager.yaml
```

Откройте **http://127.0.0.1:8090**. Укажите существующий каталог `config` вашей установки Homepage в `config_dir`. Отсутствующий каталог создаётся, но файлы создаются только после сохранения в GUI. Примеры для пустой установки — в `examples/config`.

Все параметры панели задаются в отдельном YAML-файле. Пример:

```yaml
listen: "0.0.0.0:8090"
config_dir: "/opt/homepage/config"
images_dir: "/opt/homepage/public/images"
images_url: "/images"
icons_dir: "/opt/homepage/public/icons"
icons_url: "/icons"
password: ""
# https_proxy: "http://proxy.example.com:3128"
# http_proxy: "http://proxy.example.com:3128"
# no_proxy: "localhost,127.0.0.1"
```

Запуск готового Linux-бинарника: `./home-pager-linux-amd64 -conf /путь/home-pager.yaml`. Если `home-pager.yaml` находится в текущей рабочей папке, он загружается автоматически и можно запускать без аргументов. Относительные пути в файле считаются от папки этого файла. Пустые `images_dir`/`icons_dir` означают подкаталоги `images`/`icons` внутри `config_dir`. Неизвестные параметры и ошибки YAML останавливают запуск с сообщением об ошибке. Изменения применяются после перезапуска панели.

Пароль **необязателен на любом адресе прослушивания**. `password: ""` отключает вход, непустая строка включает HTTP Basic (имя пользователя любое). Если поле `password` отсутствует, для совместимости используется `HOMEPAGER_PASSWORD` из окружения; явно пустое поле отключает и его. Значения прокси из файла имеют приоритет над окружением; явно пустая строка отключает соответствующий прокси.

Старые опции `-listen`, `-config`, `-images`, `-icons`, `-images-url` и `-icons-url` сохранены для совместимости и перекрывают соответствующие поля файла. Без файла используются `127.0.0.1:8090` и `./config`.

Если после установки Go команда ещё не видна в текущей консоли, перезапустите терминал или вызовите `C:\Program Files\Go\bin\go.exe` напрямую.

## Возможности

**«Настройки панели»** в боковом меню управляют самим Home Pager: светлая/тёмная/системная тема, обычная или компактная плотность, начальное раскрытие сервисов и закладок, подсказки, счётчики, технические имена, подписи типов блоков, раскрытие результатов поиска и открытие последнего раздела. Предпочтения сохраняются в локальном хранилище браузера, отдельно от файлов Homepage. Тема применяется сразу для предпросмотра; «Отмена» возвращает предыдущую. Есть сброс к значениям по умолчанию.

По умолчанию сервисы и закладки полностью свёрнуты — видны названия групп. Раскрытие выполняется нажатием на заголовок, поиск сам группы не разворачивает. В настройках можно выбрать раскрытие только групп или всех уровней отдельно для сервисов и закладок. Ручное раскрытие сохраняется при редактировании текущего файла; после перехода в раздел действует выбранное начальное состояние. Настройки панели не меняют `settings.yaml`, `custom.css` и тему самого Homepage.

В **Настройки → Оформление и раскладка** доступны самостоятельная настройка темы, палитры, шрифта, фона, фильтров, размытия, прозрачности и размеров карточек. Для каждой существующей группы можно выбрать полную ширину строки или вертикальный столбец, 1–8 колонок карточек, скрыть заголовок, указать вкладку, сворачивание и порядок. Вложенные группы настраиваются отдельно. Готовый макет или демонстрационные сервисы не добавляются.

Предпросмотр использует названия ваших сервисов, а показатели виджетов показывает схематично — без обращений к API сервисов и вывода их ключей. Удалённый фон загружается в предпросмотр только при включении соответствующего переключателя. Импортированные локальные фоны доступны сразу; произвольный локальный файл, который виден только Homepage, может не отображаться в панели. Предпросмотр приблизительный и не исполняет ваш `custom.js` или произвольный `custom.css`.

**«Применить к черновику»** не записывает файлы. Затем обычная кнопка **«Сохранить изменения»** сохраняет `settings.yaml` и, если изменены размеры/прозрачность карточек, отдельный помеченный блок `custom.css`. Остальное содержимое CSS сохраняется. Обе ревизии проверяются до записи, создаются резервные копии; если запись второго файла завершится ошибкой, панель пытается восстановить первый. Замена файлов не является общей атомарной транзакцией при аварийной остановке процесса. Для возврата к стандартному виду выключите **«Своя прозрачность и размеры карточек»** и сохраните — удалится только блок, созданный панелью.

Фильтры фона и размытие под карточками — взаимоисключающие режимы Homepage: панель оставляет выбранный режим при применении. Пользовательские CSS-правила могут переопределять результат; параметры размеров/прозрачности панели используют `!important` только для своих правил карточек.

- `settings.yaml`: оформление, layout, вкладки, провайдеры, быстрый поиск и любые другие поля.
- `services.yaml`: группы, вложенные группы, приложения, один или несколько сервисных виджетов.
- `bookmarks.yaml`, `widgets.yaml`, `docker.yaml`, `kubernetes.yaml`, `proxmox.yaml`.
- Произвольные дополнительные `.yaml`/`.yml` непосредственно в каталоге конфигурации.
- Редактор `custom.css` и `custom.js` без выполнения этих скриптов в панели управления.
- Визуальные поля всех вложенных объектов и списков; добавление, удаление, переименование групп и изменение порядка элементов списков. Для параметров доступны строки, числа, переключатели и null.
- В обычных строках редактора нет выбора типа YAML: тема, палитра, язык и открытие ссылок выбираются из подписанных списков, переключатели показывают «Включено / Выключено», числа вводятся в числовые поля. Для пустого значения показывается «По умолчанию». Редкая смена способа ввода доступна через `⋯`; при добавлении поля дополнительные настройки по умолчанию свёрнуты. Неизвестные значения и строки, похожие на числа, сохраняются без автоматического преобразования.
- Контекстные шаблоны доступны через компактную кнопку **`＋` в заголовке блока**. В группе предлагаются новый сервис и сервис из каталога; в сервисе — его параметры и подключение первого виджета. После подключения виджета добавление следующего доступно в разделе «Виджет / Виджеты», а внутри отдельного элемента списка — только параметры этой интеграции. Вложенные поля `headers`, `fields` и другие свойства не предлагают добавлять виджеты. По умолчанию второй виджет сохраняет первый, преобразуя `widget` в список `widgets`; явная замена выбирается отдельно. Адрес, иконка, мониторинг и другие поля сервиса сохраняются. В заголовках есть подписи «Группа», «Сервис», «Виджет», а повторяющиеся строки действий внизу карточек убраны. Для общих настроек доступны готовые параметры из встроенного каталога, а собственные поля остаются отдельным дополнительным действием.
- Перемещение блоков в визуальном редакторе: тяните за ручку `⠿` к верхней/нижней границе другого блока или используйте кнопки `↑` / `↓`. Порядок можно менять и в списках, и в объектах YAML. Сервисы и закладки можно переносить между группами: перетащите к другому сервису/закладке или в зону внизу группы; кнопка `↗` открывает выбор группы без перетаскивания. Вложенную группу нельзя перенести внутрь самой себя. Изменения порядка записываются только после «Сохранить изменения»; если в Homepage задано явное `layout`/`sort`, фактический порядок отображения может определяться этими настройками.
- Офлайн-каталог из **164 сервисных виджетов**, **13 инфовиджетов** и **50 примеров настроек** из исходников Homepage, снимок от 2 ноября 2026 года. Каталог содержит официальные примеры, включая опциональные поля; подставьте свои адреса, версии API и ключи. Это не список гарантированно настроенных интеграций.
- YAML-режим с сохранением исходного текста; переключение между YAML и формой. Визуальное редактирование сохраняет неизвестные поля, YAML-комментарии, якоря и ссылки на якоря. Форматирование YAML при сохранении формы нормализуется; сами ссылки на якоря редактируются в YAML-режиме.
- Проверка синтаксиса YAML, повторяющихся ключей, типов значений и корневого типа стандартных файлов. Ошибочный существующий файл можно открыть и исправить в редакторе кода.
- Просмотр версий до/после сохранения, скачивание файла и предупреждение о несохранённых изменениях.
- Проверка SHA-256 перед записью: если файл изменён другой вкладкой или внешним редактором, сохранение отклоняется с конфликтом.
- Резервная копия предыдущего содержимого перед каждой фактической перезаписью: `config/.home-pager-history`. Восстановление сначала загружает выбранную версию в редактор; запись происходит после нажатия «Сохранить».

Панель редактирует **файлы конфигурации**. Семантику каждого API-виджета проверяет сам Homepage: валидный YAML ещё не означает действующие ключи и доступный сервис. Для существующих параметров без отдельной подсказки доступны универсальные поля и YAML-режим.

Переменные `{{HOMEPAGE_VAR_...}}` и `{{HOMEPAGE_FILE_...}}` сохраняются как есть: панель не раскрывает их через окружение процесса. Их значения, `HOMEPAGE_ALLOWED_HOSTS`, параметры авторизации/MCP, Docker labels, Kubernetes annotations, mounts и другие настройки запуска задаются в окружении/Compose/манифестах самого Homepage. Панель не изменяет конфигурацию оркестратора и не перезапускает контейнеры. Каталог `config` на Kubernetes должен быть доступен на запись; read-only ConfigMap напрямую не подходит.

После сохранения нажмите кнопку обновления в самом Homepage. Для некоторых изменений, например добавления локальных изображений, документация Homepage требует перезапуск контейнера.

## Загрузка фоновых изображений

В `Настройки` нажмите **«Загрузить фон»**, вставьте публичную HTTP/HTTPS-ссылку, выберите **JPEG, PNG или WebP** и максимальные размеры. После загрузки появится предпросмотр. **«Применить фон»** меняет только черновик настроек; затем нажмите **«Сохранить изменения»**. Остальные параметры объекта `background` (blur, brightness, opacity и другие) сохраняются. Файлы изображений записываются сразу после конвертации; закрытие диалога не удаляет уже созданный файл.

Вход: JPEG, PNG, статичный WebP, GIF (первый кадр). SVG/AVIF не поддерживаются. WebP и PNG сохраняются без потерь; качество 1–100 задаётся для JPEG. Прозрачность в JPEG заменяется белым фоном. Метаданные исходника не переносятся. Уменьшение сохраняет пропорции, без обрезки и увеличения. Лимиты: 20 MiB, 16 мегапикселей, до 8192 px по стороне. Загрузка с частных, loopback и link-local адресов отклоняется; перенаправления проверяются при подключении.

По умолчанию файлы помещаются в **`<config>/images`**, а путь для Homepage — `/images/background-<hash>.<format>`. Каталог с файлами необходимо предоставить Homepage как **`public/images`**. Доступ к предпросмотру в панели защищён той же авторизацией, что и API.

Сетевые настройки загрузчика: до 20 секунд на TLS, до 30 секунд на заголовки ответа; одна повторная попытка при сетевом таймауте, общий бюджет загрузки — 90 секунд. Используются стандартные `HTTPS_PROXY`, `HTTP_PROXY` и `NO_PROXY` окружения процесса панели. Если прямое подключение к сайту с вашего сервера недоступно, задайте прокси и перезапустите панель:

```sh
# В home-pager.yaml задайте https_proxy: "http://proxy.example.com:3128"
./home-pager-linux-amd64 -conf ./home-pager.yaml
```

В Docker эти переменные нужно явно передать в `environment` сервиса панели. Проверка TLS-сертификатов остаётся включённой. Настроенный администратором прокси считается доверенным: он может находиться в локальной сети и самостоятельно разрешает DNS назначения; адрес изображения и каждое перенаправление дополнительно проверяются панелью на публичность.

Для обычной установки задайте `images_dir: /opt/homepage/public/images` в конфигурации панели:

```sh
./home-pager-linux-amd64 -conf ./home-pager.yaml
```

При другом публичном пути задайте `images_url: /wallpapers`. Это путь в URL самого Homepage, а не адрес панели Home Pager. Обновлённый Linux-бинарник остаётся самостоятельным: ImageMagick, ffmpeg и libwebp устанавливать не требуется.

Для Docker создайте `./config/images` с правами записи для панели и чтения для Homepage. В **существующий сервис Homepage** добавьте:

```yaml
volumes:
  - ./config:/app/config
  - ./config/images:/app/public/images:ro
```

Панель продолжает использовать `./config:/config` из `compose.yaml`. Оба монтирования должны ссылаться на один и тот же абсолютный каталог хоста (особенно если Compose-файлы находятся в разных папках). После добавления нового изображения может потребоваться перезапуск Homepage: это ограничение обнаружения файлов в Homepage. Сохранённые изображения автоматически не очищаются.

## Загрузка иконок

В разделах **«Сервисы»** и **«Закладки»** нажмите **«Загрузить иконку»**, выберите нужный элемент и источник: **URL** или **файл с компьютера**. Рядом с существующим полем `icon` есть кнопка `▧`, которая сразу выбирает этот элемент. Отсутствующее поле `icon` добавится автоматически. После предпросмотра нажмите **«Применить иконку»**, затем **«Сохранить изменения»**.

Входные форматы: PNG, JPEG, GIF (первый кадр), статичный WebP; выходные: PNG, WebP или JPEG. По умолчанию — PNG и ограничение 256×256 с сохранением пропорций, без увеличения маленьких изображений. Прозрачность сохраняется в PNG/WebP. SVG, ICO и AVIF для импорта пока не поддерживаются; существующие ссылки на такие иконки можно по-прежнему задавать вручную в `icon`.

Иконки хранятся в **`<config>/icons`**, путь для Homepage — `/icons/icon-<hash>.<format>`. Можно задать `icons_dir: /opt/homepage/public/icons` и, при другом URL, `icons_url: /custom-icons`. Для Docker добавьте в существующий сервис Homepage монтирование того же каталога хоста:

```yaml
volumes:
  - ./config/icons:/app/public/icons:ro
```

Создайте этот каталог с правами записи для панели и чтения для Homepage. После добавления нового файла Homepage может потребовать перезапуск. Как и фоны, иконки записываются при загрузке, а применение к конфигурации происходит только после сохранения черновика. Поля сервиса, виджеты и комментарии остаются на месте. Загрузка файла с компьютера не требует доступа сервера к внешнему сайту. Для загрузки по URL действуют те же таймауты, настройки прокси и ограничения адресов, что и для фонов.

## Docker

Панель запускается рядом с Homepage и получает **тот же каталог конфигурации**. Docker socket ей не нужен.

```sh
# Отредактируйте параметры в home-pager.docker.yaml.
docker compose up -d --build
```

В `compose.yaml` замените `./config:/config` на фактический путь к каталогу Homepage. UID:GID панели должны иметь права на каталог, включая создание временных файлов и резервных копий. Для существующих файлов сохраняются POSIX-права; при замене меняется владелец на пользователя панели. Новые файлы имеют права `0600`, поэтому запускайте панель под тем же UID, что и Homepage. Монтируйте каталог целиком, а не отдельные файлы: сохранение использует временный файл и переименование.

Compose монтирует `home-pager.docker.yaml` в `/etc/home-pager.yaml`; в этом файле задаются адрес, пути, необязательный пароль и прокси. Пароль в примере отключён. Порт в Compose опубликован на `127.0.0.1`; для доступа по сети замените привязку порта на `8090:8090`.

## Проверки

Для виджета **Grafana** выбирайте полный URL (`http://host:3000` или HTTPS), версию совместимости `2` для Grafana новее 10.4 и источник оповещений **«Встроенный Alertmanager Grafana»**, если внешний источник не настроен. В новых шаблонах используется `alerts: grafana`. Значение `alertmanager` обращается к внешнему источнику с UID `alertmanager` и может давать `data source not found`. Виджет также запрашивает `/api/admin/stats`: этот API требует Basic-аутентификацию пользователя с правами серверного администратора Grafana; service account token для него не подходит. Панель подписывает эти поля отдельно и проверяет наличие протокола в URL перед сохранением визуальной формы.

```sh
go test ./...
go vet ./...
```

Для необязательных DOM-интеграционных тестов интерфейса требуется Node.js 20+ и собранный `home-pager` / `home-pager.exe`:

```sh
npm ci
npm test
```

Тесты запускают настоящий Go API с временным каталогом и проверяют взаимодействие frontend с ним через JSDOM. Они не заменяют визуальную проверку в браузере.

## Структура

```text
main.go                 HTTP API, YAML, авторизация, запись и резервные копии
app_config.go           Конфигурация запуска панели из YAML-файла
appearance.go           Согласованное сохранение настроек и блока CSS оформления
images.go               Загрузка по URL, конвертация и предпросмотр фонов
web/                    Встроенный интерфейс без runtime-зависимостей
web/appearance.js       Визуальная настройка оформления и раскладки
web/catalog.json        Офлайн-каталог примеров Homepage
cmd/catalog/            Генератор каталога из исходников Homepage
main_test.go            Тесты API и работы с файлами
tests/ui.test.cjs        DOM-интеграционные тесты с настоящим API
examples/config/        Минимальный пример конфигурации
Dockerfile, compose.yaml
```

Обновление каталога после получения исходников Homepage:

```sh
go run ./cmd/catalog -source /path/to/homepage -out web/catalog.json
go build -o home-pager .
```

Каталог — снимок документации, а не строгая схема: неизвестные и будущие настройки доступны вручную. Генератор извлекает первый YAML-пример каждого виджета и YAML-примеры из страницы Settings. Снимок датирован в `cmd/catalog/main.go`; при обновлении измените дату.

Ограничения: один YAML-документ на файл, до 2 MiB, дополнительная конфигурация только в корне каталога, символьные ссылки отклоняются. История хранится локально без автоматической очистки, включая старые значения секретов. Конфликт проверяется перед записью; произвольный внешний процесс, меняющий файл ровно между проверкой и переименованием, не участвует в блокировке панели. На Unix замена через rename атомарна; Go не гарантирует атомарность rename на Windows. При сбое записи предыдущая версия доступна в истории.

Источники структуры и поведения: [конфигурация](https://gethomepage.dev/configs/), [настройки](https://gethomepage.dev/configs/settings/), [сервисы](https://gethomepage.dev/configs/services/), [виджеты](https://gethomepage.dev/widgets/), [исходники](https://github.com/gethomepage/homepage).

### Галереи иконок

В окне выбора иконки по умолчанию открывается галерея с поиском и миниатюрами.
Готовые наборы: Dashboard Icons, selfh.st, Simple Icons, Material Design Icons,
Lucide, Tabler (Outline/ Filled), Bootstrap Icons, Heroicons (Outline/Solid),
Font Awesome Free (Solid/Brands). Ручное подключение баз удалено.

PNG из Dashboard Icons и selfh.st скачивается на сервер и конвертируется
в локальную иконку. SVG из остальных наборов применяется как внешняя ссылка:
после загрузки предпросмотра нажмите «Применить иконку» и сохраните конфигурацию.
Локальная конвертация и массовая загрузка SVG пока недоступны.
Миниатюрам и внешним SVG нужен доступ браузера к CDN.

Для массового скачивания PNG выберите набор и введите `grafana` (содержит),
`grafana*` (начинается с) или `*grafana*`, затем «Скачать найденные (N)».
`?` означает один символ, регистр не учитывается. Скачиваются все совпадения,
включая ещё не показанные карточки. Результат — PNG до 256 × 256; пути и ошибки
появляются под кнопкой. Остановка или закрытие окна отменяет остаток очереди,
уже сохранённые файлы остаются. Конфигурация сервисов не меняется.

Списки имён встроены в бинарь. Обновление при сборке: `node cmd/update-icons.cjs`.
Источник и лицензия каждого набора доступны в галерее.

Источник «Загруженные иконки» показывает файлы из настроенного `icons_dir`:
миниатюры, поиск по имени, порционная выдача и обновление списка. Поддерживаются
PNG, JPEG, WebP и GIF, включая файлы, скопированные в каталог вручную.
Выбор добавляет существующий путь в черновик сервиса или закладки без повторного
скачивания; затем нажмите «Применить иконку» и сохраните изменения.

Кнопка ⧉ в заголовке блока создаёт копию группы, сервиса, закладки или виджета
рядом с исходным. Для именованных элементов списков подбирается уникальное имя
с пометкой «копия». Копирование одиночного виджета сервиса преобразует `widget`
в список `widgets`; копирование всего списка виджетов добавляет копии в этот же
список. Для остальных полей-объектов редактор запрашивает новое имя параметра.
Вложенные значения и комментарии сохраняются, внутренние YAML-якоря получают
уникальные имена. Изменения записываются только при сохранении файла.

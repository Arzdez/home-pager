UniFi · Custom API templates

Visual port map: add “UniFi · Схема портов” to a service and configure its URL and API key. In Home Pager → Scripts JS, enable UniFi visual port maps and enter the exact Homepage group and service names. Choose gateway (one row) or switch (two rows). Save custom.js and reload Homepage. The map uses the existing Homepage service proxy; controller credentials are never embedded in the script. Without the script the card shows a basic port/client/uplink summary.

The map separates SFP ports, colors connected ports by negotiated speed, and marks WAN/uplink, PoE, aggregation and mirroring when reported by the controller. Click a port for its name, state, speed, error and drop counters. A failed refresh is marked as stale. No device or port configuration is changed.

Two variants: system (CPU, RAM, WAN latency) and WAN traffic (download, upload, received bytes, sent bytes). System has three mappings; WAN traffic has four. Both use Homepage's standard block display.

Additional catalog entries: WAN Health (state, availability, link speed; latency remains in the System card), Uplink Errors (RX/TX errors and dropped packets), Device (CPU/RAM/load/update status, client/experience/uplink overview, or diagnostics), Wi-Fi (2.4 GHz / 5 GHz examples), and Ports (state, speed, RX/TX errors and drops).

Wi-Fi templates reference radio_table_stats.0 / radio_table_stats.1; check the entry's radio value before selecting an index. Ports reference port_table.0; replace 0 with the array index matching the desired port_idx. Index is not the physical port number. Recheck indices after firmware or hardware changes.

Port templates use display: list to show all six fields. Other templates use up to four block fields. Port speed is the controller's reported value and can be stale when the port is down. Experience scores can be unavailable (-1). Errors, drops and retries are counters, not packet-loss percentages. Load average is not CPU utilization. Update status reflects the controller's upgradable flag.

Set the controller URL, internal site name (normally default, not the display name) and gateway MAC in the endpoint URL. It selects one device explicitly, so the mappings do not depend on the order of the device list.

Create an API key in UniFi Network → Control Plane → Integrations. Set HOMEPAGE_VAR_UNIFI_API_KEY in the Homepage container environment, or replace the header placeholder with the key in the editor. A login/password does not work with Custom API: it cannot perform UniFi's session login.

This template uses the controller's legacy /proxy/network/api/s/{site}/stat/device/{mac} endpoint, also used by UniFi integrations. API key access and fields depend on the installed UniFi version. The endpoint must return HTTP 200 with one device in data. System and WAN fields were inspected on UCG Ultra; verify API key access on your controller before enabling the template. Traffic counters are cumulative, not daily totals. The API's bytes/second rates are formatted by Homepage as bits/second.
